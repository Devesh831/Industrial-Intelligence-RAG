# RAG design notes

The prototype extracts text page by page with pypdf, builds overlapping 160-word chunks with 40-word overlap, encodes them with `sentence-transformers/all-MiniLM-L6-v2`, and stores normalized vectors and filename/page metadata in local Chroma. Cosine retrieval returns up to three chunks, filtered by a configurable distance threshold. `google/flan-t5-small` runs locally on CPU and generates an answer from short excerpts. Sources and snippets are shown alongside the answer. The separate architecture slide depicts this flow.

Page boundaries make citations easy to inspect but can split tables or cross-page passages. Word windows are simple and may cut sentences; a production system should preserve sections and tables, use token-aware limits, and apply OCR to scanned pages. Some PDFs emit parser warnings; text extraction must be audited. The default 0.65 cosine distance is a starting heuristic, not a calibrated confidence score. Create a labeled question set spanning relevant and unanswerable queries and select thresholds from validation results.

The prototype blocks a small list of credential or sensitive-identifier requests, returns a fallback if no retrieved hit passes the distance threshold, and instructs the model to use evidence and ignore instructions inside retrieved content. This is a demonstration, not a comprehensive security boundary: regex filtering misses variants, documents can contain prompt injection, and a citation or similarity score does not verify that a generated sentence is supported. Check sources manually; add access control, stronger classification, prompt isolation, sentence-level citation verification and human review for operational decisions.

Measure retrieval precision@k and recall@k with relevance labels, and answer faithfulness and abstention quality with reviewed question-answer pairs. Track latency, no-answer rate, index freshness and extraction failures without logging sensitive content. For ten times as many documents, batch and incrementally update embeddings using content hashes, version documents and index metadata, shard or move the index to a managed service, and add hybrid BM25 plus reranking where evaluated beneficial. For 100+ simultaneous users, separate ingestion from serving, cache repeated retrievals, bound queues, batch model requests and scale stateless API workers; profile GPU or optimized CPU inference before choosing capacity. Cloud costs can be controlled with CPU embedding, shared vector storage, autoscaling and idle shutdown. These are proposals, not tested capacity claims.
